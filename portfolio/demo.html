Product Demo · 产品展示

IP 群高光

把微信群里最能激活大家的内容，转化为作品样本、行动清单、社群记忆和长期知识资产。

形态 · Markdown 工作流 + 静态展示页 阶段 · MVP / Vol.001 验证中 周期 · 每周一个加工循环

Problem & Solution

群聊里的好内容，正在被刷走

这不是「AI 总结群聊」。总结抹平了价值的不均匀分布；我们要做的是找到价值最集中的瞬间，把它剪出来。

核心问题

一段精彩发言、一个被刷屏的作品、一场吵出真知的讨论——24 小时后就沉到聊天记录的几百楼之下，再也没人翻得到。

群主想整理，但「读完全部消息再总结」成本太高，整理出来的东西又像会议纪要，没人想回复。

产品解法

不总结全部聊天，而是抓反应峰值。判断内容是否值得剪辑，看它在群里引发了什么——追问、点赞、围观、观点碰撞。

围绕反应峰值做三件事：剪辑成型、沉淀记忆、反哺创作者。

Three Types of Highlights

三类高光事件

每周从群聊里识别并加工以下三类内容，它们分别对应周刊里不同的栏目和知识库。

01 · 群主观点

观点高光

一个判断、一次纠偏、一段干货输出，引发认同或追问。是「本周洞察」与方法论库的主要来源。

02 · 群友作品

作品高光

群友分享自己的产出——文章、海报、账号、实验结果，获得关注与反馈。是「成员高光」与案例库的来源，也是反哺创作者最直接的部分。

03 · 话题讨论

讨论高光

一个问题引发多人接力，出现不同立场或新角度。是「高价值讨论精选」与下周选题库的来源。

Collaboration

三方分工

这个项目本身的搭建过程，也是一次「人 + 多个 AI 协作」的实践——判断力、内容生成、工程结构分属不同角色。

用户

产品判断

决定要不要做、定位是什么、MVP 边界画在哪、质量标准如何定义，以及每期产出的最终发布把关。这部分不可外包。

GPT-Codex

内容生成执行

在工作流的「内容生成」环节，按既定 prompt 和编辑标准产出周刊 / 短版 / 归档内容的初稿。

Claude Code

系统工程搭建

设计目录结构、撰写六个 prompt 的编辑标准、构建知识库字段格式、搭建本展示页，把想法变成可重复运行的系统。

MVP Success Bar

MVP 成功标准

每期产出对照四档自评，判断这一期落在哪个区间，下一期该往哪个方向使劲。

平淡版本
像普通周报、流水账，没人想回复。
合格版本
能清楚复盘本周高光，有可执行建议。
优秀版本
被提到的人愿意回复，群友觉得有用。
惊艳版本
群友开始主动想被收录，项目能放进求职作品集。
终极标准

这份东西有没有让一个普通微信群，突然显得像一个正在共同创作的社区？

Roadmap

后续路线

四个方向按顺序推进，每个方向只有在前一个被验证后才启动。

01

外显化

把产出从「群主自己看」变成群友可见、可参与的形态，让「被收录」成为群内的可见认可。

02

专门化

针对不同类型社群（技术群 / 读书会 / 商业社群）调整筛选标准和栏目结构。

03

自动化

替换人工粘贴素材的输入方式，但筛选与改写始终保留 AI + 人工复核。

04

复利化

用知识库反向生产新内容——「三个月内最常提到的方法论」「悬而未决的问题专题」。
