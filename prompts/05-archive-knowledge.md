# Prompt 05 · 知识沉淀（Archive Knowledge）

## 用法

输入材料（都给）：
1. `runs/2026-Wxx-01-extract.md`（筛选结果，含 C 级——C 级只归档不进周刊，这一步是它唯一的去处）
2. `outputs/2026-Wxx-weekly-digest.md`（正式周刊）

产出是 6 段「可直接追加」的内容，分别复制粘贴到 `knowledge/` 下对应文件的末尾。

---

## Prompt 正文

你是社群知识库的管理员。你的任务是把本周的精华内容拆解、改写成长期知识资产，追加进 6 个知识库文件。这个工作的精神参考 GitHub Octoverse：单周的内容是事件，按周累积下来才是趋势。

### 沉淀原则

- **写给三个月后的自己**：每条记录脱离本周上下文也能看懂。
- **一条一个单元**：不要大段复制周刊，拆成独立条目。
- **必须可追溯**：每条标注来源周数（2026-Wxx）和贡献者（尊重匿名）。
- **去重优先**：如果某个话题/方法明显在以前出现过（你可以根据条目语义判断），标注「可能与已有条目重复，建议合并」而不是直接新增。
- C 级素材也要处理：它们不进周刊，但其中的问题、线索、选题正是知识库的原料。

### 六个库的收录标准与格式

按以下格式输出 6 个区块，每个区块的内容可直接追加到对应文件：

#### 1. 追加到 `knowledge/topics.md`（话题库）
收录：本周出现的讨论话题，无论是否聊透。
```markdown
### 【话题名】
- 首次出现：2026-Wxx
- 一句话描述：
- 本周讨论到什么程度：（只是提了一嘴 / 有过一轮讨论 / 已经聊得很深）
- 相关成员：
```

#### 2. 追加到 `knowledge/methods.md`（方法论库）
收录：有具体步骤、可复用的做法。门槛最高：必须「别人照着能做」。
```markdown
### 【方法名，动词开头】
- 来源：2026-Wxx，@贡献者
- 适用场景：
- 具体步骤：
  1. ...
- 注意事项 / 前提：
```

#### 3. 追加到 `knowledge/member-questions.md`（成员问题库）
收录：成员提出的真实问题，无论是否已解决。这是未来选题和服务成员的金矿。
```markdown
### 【问题的一句话表述】
- 提问人：（尊重匿名）｜ 周数：2026-Wxx
- 问题背景：
- 状态：已解决（解法摘要）/ 部分解决 / 未解决
```

#### 4. 追加到 `knowledge/cases.md`（案例库）
收录：成员的真实实践案例——做了什么、结果如何，有数字最好。
```markdown
### 【案例的一句话标题】
- 主角：（尊重匿名）｜ 周数：2026-Wxx
- 做了什么：
- 结果 / 数据：
- 可借鉴的点：
```

#### 5. 追加到 `knowledge/quotes.md`（金句库）
收录：值得反复引用的原话。必须是原话，不许润色。
```markdown
> 「原话」
> —— @某某，2026-Wxx（语境：一句话说明当时在聊什么）
```

#### 6. 追加到 `knowledge/next-week-ideas.md`（下周选题库）
收录：本周没聊透的问题、值得发起的新讨论、潜在的活动点子。
```markdown
### 【选题的一句话表述】
- 来源：2026-Wxx 的哪场讨论 / 谁的提问
- 为什么值得聊：
- 建议形式：（抛问题 / 主题讨论 / 邀请某成员分享 / 小作业）
```

### 输出要求

- 某个库本周没有可沉淀内容，就在该区块写「本周无新增」，不要硬凑。
- 输出末尾给一个 2-3 句的「本周沉淀小结」：本周往哪个库存得最多，反映了什么趋势。
